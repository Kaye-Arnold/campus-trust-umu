# CampusTrust trust and safety model

## What “Listed” means

A **Listed provider** is a service provider record added to the CampusTrust directory. “Listed” does not mean that CampusTrust guarantees the provider's conduct, price, availability, identity, or safety. The app intentionally avoids calling providers “verified” until a documented operator process exists.

## Provider onboarding

Providers currently apply through the linked Tally form. The directory owner is responsible for reviewing submissions and deciding whether to add, update, pause, or remove a record. Applications should be checked before a record is published, but the current repository does not automate or evidence that review.

Before launch, the directory owner must document who performs this review, what evidence is checked, and how often contact details are reconfirmed.

## Reviews

Only signed-in users can submit one immutable 1–5 review per provider. Reviews are associated with the submitting account and are publicly readable. Reviews are community feedback, not a guarantee of service quality.

Users should not include phone numbers, private information, accusations they cannot substantiate, or abusive content in reviews.

## Reporting and response

Until an in-app report workflow is added, users should contact the directory operator through the project’s designated support channel to report:

- unsafe or fraudulent providers
- wrong phone numbers
- impersonation
- inappropriate or fraudulent reviews
- outdated listings

The operator should record the report, pause a listing where immediate safety is a concern, investigate, and record the outcome. Do not publish a “verified” badge without an operational process to support it.

## Minimum launch ownership

A named UMU Nkozi directory operator must own provider approvals, corrections, removals, and review complaints. If no operator is available, CampusTrust should remain in controlled pilot rather than presenting the directory as a dependable public trust service.
